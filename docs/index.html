AEGIS

Verifiable signing firewall for agent wallets. AEGIS screens a transaction before the wallet signs it — decodes it, simulates it, judges it against a 30-rule policy — and seals the verdict into a proof anyone can verify.

Everything runs in your browser. This page bundles the exact engine code from the repository (engine/screen.js, unmodified) and reads BSC through public RPC endpoints and Sourcify. Read-only by construction: no keys, no signing, nothing is sent. A live screening takes roughly 10–60 seconds — it downloads verified contract sources and probes chain state.

The engine decodes the call, censuses every privileged function of the target contract, simulates the call against live chain state, evaluates the 30 rules, and seals the verdict into a Poseidon commitment — the input of the VerdictCommit circuit.

Verdict record

Canonical fields — sealed by the commitment

commitment = Poseidon(fields[0..5], verdict), computed with circomlibjs — the same Poseidon as circuits/verdict_commit.circom. The rules bitmap inside fields[4] binds the verdict to the exact rules that fired and the effects observed, so the verdict can be re-derived from the report alone.

Rules marked NOT_IMPLEMENTED cannot be evaluated by engine v1: B08, B11, B12, W06, W07, W08 and A03 need holder distribution, LP holder and lock status, USD pool liquidity, or deployer labels from a keyed explorer or indexer. An unimplemented rule is reported, never treated as passed. Some implemented rules are probe-conditional and also report NOT_IMPLEMENTED for a given screening when their probe cannot run — the evidence column says which.

The policy — 30 rules, three bands

Evaluation is deterministic and severity-ordered: any BLOCK rule fired makes the verdict BLOCK; else any WARN rule makes it WARN; else ALLOW. The verdict is a pure function of the fired-rule bitmap, and no model judgement is in the verdict path. The full rule set, thresholds, and field mapping are in POLICY.md.

Block14 rules — verdict 2

Do not sign. There is no override path in the agent. Fires on, among others: an unlimited approval to an untrusted spender (B01), a simulation that reverts — the engine fails closed (B04), and a live hidden mint with no enforced supply cap (B06).

Warn13 rules — verdict 1

Do not sign autonomously. The fired rules go to the human, who confirms the exact preview or walks away. Fires on, among others: retained authority that is clean today but changeable tomorrow (W01, W02, W05), and a token whose own swapback path swaps with zero slippage protection (W11).

Allow-context3 rules — verdict 0 contributors

Context checks that can only support an ALLOW. They never raise a verdict; they record why a clean call is clean, so an ALLOW is evidence, not an absence of checks.

Honest labels. Engine v1 implements 23 of the 30 rules; the other seven report NOT_IMPLEMENTED in every report rather than passing silently. A verdict is anchored to one block and expires with it. What the engine cannot detect at all — off-chain intent, time-delayed traps, novel logic bugs — is stated in POLICY §8. The proof proves the report, not the world.
