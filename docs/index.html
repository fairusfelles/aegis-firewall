AEGIS

Verifiable Signing Firewall for Agent Wallets — don't trust the agent. Verify it.
GitHub Policy Circuit Engine

AEGIS screens a transaction before an agent wallet signs it: it decodes the call, censuses every privileged function of the target contract, simulates the call against live chain state, and evaluates a deterministic rule set (30 rules, POLICY.md) into an ALLOW / WARN / BLOCK verdict. The verdict, the exact rules that fired, and the observed effects are sealed into six canonical fields and a Poseidon commitment — the inputs of the VerdictCommit circuit, proven and verified on zkVerify (see the repo's SPIKE.md).

This demo runs 100% in your browser. There is no AEGIS server. The page bundles the exact engine code from the repository (engine/screen.js) and talks directly to public BSC RPC endpoints and Sourcify from your machine. It is read-only by construction: no keys, no signing, no transactions — only chain reads and simulated calls. A screening takes roughly 10–60 seconds: it downloads verified contract sources and probes chain state.
Honest labels. A verdict is computed against the chain state at one specific block (shown with every result) and expires with that block. The three cases below are real calls the agent wallet sarah.ai faced; re-screening them today judges today's state — a window that has closed correctly reads BLOCK now. Also: 7 of the 30 rules always report NOT_IMPLEMENTED in engine v1 (they need a keyed explorer/indexer source). They are listed as such in every report — never silently passed.
